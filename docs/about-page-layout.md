# About Page Layout

## Goal

Present a concise **personnel record** that explains professional identity,
operating strengths, experience, and current interests without turning the page
into a resume dump.

This page should use a quieter version of the ornamental system. Its tone can be
more personal than the Work and case-study pages while retaining their structure.

## Content structure

### 1. Identification block

Include:

- Name
- Current professional description
- Location or working region
- Availability, if useful and current
- One sentence that distinguishes design-engineering work from general product
  design or frontend development

Avoid a large list of self-assigned titles.

### 2. Profile narrative

Use two or three compact paragraphs. The narrative should explain:

- The type of problems you work on.
- How design and implementation connect in your practice.
- The kinds of teams or product contexts where that combination is valuable.

Keep the reading measure to approximately two-thirds of the page width.

### 3. Operating principles

Convert “What I bring to a team” into four ruled entries rather than feature
cards:

```text
01 / PRODUCT JUDGMENT
Define the problem, customer need, and tradeoffs before polishing the surface.

02 / INTERFACE CRAFT
Carry interaction, responsive behavior, and accessibility through delivery.

03 / SYSTEMS THINKING
Connect components, tokens, documentation, and governance.

04 / FRONTEND DELIVERY
Use production code to resolve the details that static artifacts cannot.
```

The language above is illustrative and should be edited to reflect actual working
practice.

### 4. Experience log

Use a compact chronological record rather than reproducing every resume bullet.
Each entry should contain:

- Period
- Organization
- Role
- One concise scope or result statement

A separate downloadable resume can carry the full employment record if needed.

### 5. Current direction

End with the roles, problems, or collaborations currently of interest and a clear
path to Contact.

## Image treatment

A portrait is optional. If used:

- Place it in the narrow rail or beside the opening narrative.
- Use one consistent ratio such as 3:4.
- Add a factual caption rather than a decorative slogan.
- Reserve registration marks for this single figure.

If no suitable portrait exists, do not fill the space with abstract military
imagery. The capability rail can carry the composition on its own.

```text
| BASE / INDIANAPOLIS, US          |
+----------------------------------+
| PROFILE                          |
| Narrative...                     |
+----------------------------------+
| 01 / PRODUCT JUDGMENT            |
| Explanation...                   |
|                                  |
| 02 / INTERFACE CRAFT             |
| Explanation...                   |
+----------------------------------+
| EXPERIENCE LOG                   |
| 2023-NOW / ROLE                  |
+----------------------------------+
```

- Move status metadata directly below the introduction.
- Keep principles in one column.
- Keep experience entries chronological and concise.
- Remove any edge legend rather than rotating or compressing it.

## Ornament

Use:

- One section index.
- One status metadata group.
- Thin rules between profile, principles, and experience.
- Optional registration marks around one portrait.

Avoid:

- Skill meters or proficiency percentages.
- A wall of technology logos.
- Decorative employee numbers, security clearances, ranks, or classifications.
- Multiple boxed biography sections.

## Alternative layout

A more editorial version could pair the profile with a large portrait and place
experience in a wide lower band. This would feel more personal, but it would make
the page more dependent on photography. The personnel-record layout is the more
durable default.

## Review questions

- Does the opening explain what makes the practice distinct?
- Is the page personal without becoming biographical filler?
- Do the operating principles describe demonstrated behavior rather than traits?
- Can experience be scanned without competing with the main narrative?
- Is every piece of status metadata accurate and maintainable?
